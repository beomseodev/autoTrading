# 알림 확장 최종 사용자 흐름 검토

검토일: 2026-10-25. [기능별 실행 기록](../plans/2026-10-25-alert-extensions.md), [설정·운영 절차](../stock-alerts-operations.md).

승인된 9개 확장을 순서대로 TDD로 구현하고 기능별 네 역할 검토 후 다음 기능으로 진행했다. 기존 10종을 포함한 19종 조건, 채널별 일간·주간 이메일과 웹 푸시의 개발 범위다. 자동 주문·증권계좌 연결은 이번 계획에 포함되지 않는다.

## 실제 참여와 판정

Orca run `run_b05fbfd8e6aa`에서 비판·가능성·외부인·확장성 네 역할이 독립 원문 검토했다. 모두 기본 Codex 설정이며 누락·공급자 대체는 없다. 주 세션이 구현과 실행 검증을 담당했다. 실사용자 관점의 시나리오 검토이며 실제 외부 사용자 인터뷰나 운영 수신 실험은 아니다. 외부인은 계획 문서를 읽는 과정에서 기존 검토 요약을 함께 본 한계를 보고했고, 다른 역할의 원문 보고서는 읽지 않았다.

첫 검토의 필수 수정 네 건을 채택했다. 가능성·확장성 역할은 새 필수 코드 수정 없이 검증 범위와 운영 조건을 명시하도록 권고했다. 비판·외부인의 각 1회 후속 검토에서 기존 필수 지적 모두 해소·추가 필수 수정 없음으로 확인했다. 외부인의 비차단 권고인 마지막 OFF 복귀·첫 규칙 안내의 직접 assertion도 추가했다. 로컬 원문은 `.team-review/extensions-final-*.md`이며 보고서를 대조한 뒤 모든 최종 검토 작업자를 회수했다.

## 사용자 흐름과 자동 검사

- 계정별 저장·복구: 다른 계정의 보유·초안·규칙 접근 차단, 실패/응답 유실/충돌 후 입력 유지, 저장 자산과 실험실 가상 입력 분리.
- 등록·평가: 종목명/코드/거래소/통화 확인, 보유종목 선택 가져오기와 부분 실패 재시도, 확장 조건 등록·수정·정지·재개, 최초 기준 설정과 데이터 보류 구분.
- 결과 이해: 읽을 수 있는 조건·단위·자료 기준일, 정보 원문 링크·취소·정정, 접수와 도착 구분, 운영자의 비공개 집계.
- 수신 설정: 채널별 동의/주기, 이메일 해지의 푸시 독립성, 푸시 명시 권한 요청·거절·키 교체·부분 성공 복구·구독 해제·계정 삭제.
- 기존 대시보드·실험실: 보유/목표 계산, 위젯 크기·순서·가시성, 불완전 시세 경고, 로딩/실패 복구, 세 분석 모드, 모바일 가로 넘침 및 키보드 조작.

격리 PostgreSQL 17을 사용한 전체 Python 검사 **400 통과, opt-in 부하 3개 제외**. Node **43 통과**. 실제 headless Chrome의 알림·대시보드·로딩/실험실 세 흐름 통과. Chrome HTTP와 PushManager/Notification은 모사했고, 웹 푸시 암호화는 실제 라이브러리 출력의 로컬 복호화로 확인했다. 운영 API·메일·푸시 서비스는 호출하지 않았다.

## 부하 결과와 해석 범위

| 검사 | 입력과 확인한 결과 |
| --- | --- |
| 기존 가격 조건 | 50사용자·100종목·5,000지정가격 규칙, 공유 가격 조회 100회·메일 묶음 50개. 재개 호출 159.48/60.66초 |
| 혼합 기능 | 50사용자·100종목·19종×50=950규칙, 이메일·푸시 100묶음, 푸시 250기기. 공유 삭제 자료 종류별 9,000건과 SEC 요청 제한 처리. 모의 전송 2초·429 이후 재시도로 5분 간격 7회 안에 완료 |
| 누적 이력·주간 분량 | 1사용자·100규칙·180일/18,000이벤트·400일/800발송 이력. 주간 후보 700건 중 기발송 1건 제외, 699개 ID 집합 확인. 최종 준비 2.47초, 정정 1.13초 |
| 배당 비교 | 400개 항목을 대상으로 50회 비교 1.42초. 699신호 메일 envelope JSON은 약 402KB |

기존 가격 부하 1개 통과 후, 마지막 수정까지 반영한 혼합·누적 부하 **2개가 133.11초에 통과**했다. 혼합 호출 최대값은 모의 지연 포함 183.12초, 메일 시도 55회·푸시 시도 300회였다.

5,000개 가격 규칙 검사와 950개 혼합 규칙 검사는 서로 다른 구성이다. 700건은 대표 주간 분량이며 공시·일정은 한 규칙에서 여러 사건을 만들 수 있어 전체 상한이 아니다. 혼합 검사의 지연은 가상 시계로 더했고 재개 시각·재시도 due를 앞당겼다. 두 번 시세 확인이 필요한 냉간 캐시, 실제 계약 quota/네트워크 지연, 50사용자의 400일 누적과 약 200만 완료 task 정리 비용을 모두 검증한 결과가 아니다. 누적 검사의 400일은 발송 기준일이며 모든 created_at을 과거로 두고 만료 삭제 비용까지 측정하지 않았다. 배당 비교는 메모리 계산이며 400일 공유 삭제 자료의 반복 DB 읽기 비용과 구분한다.

재현 명령은 `ALERT_TEST_DATABASE_URL`에 격리 DB를 설정한 뒤 `python -m pytest -q`, `node --test tests/*.cjs`, `node tests/browser/stock-alerts.cjs`, `node tests/browser/dashboard.cjs`, `node tests/browser/loading.cjs`다. 부하는 `ALERT_RUN_LOAD_TEST=1`로 `tests/test_stock_alert_load.py` 및 `tests/test_alert_mixed_load.py`를 실행한다. DB 검사는 같은 DB에서 병렬 실행하지 않는다. 상세 수치는 로컬 `output/stock-alert-{load,mixed-load,mature-load}.json`에 있으며 Git에는 포함하지 않는다.

## 운영 전에 남은 검증

공급자 계약과 종목 커버리지, 실제 quota·응답 지연에서 오전 마감 충족, 운영 DB·Cron·마이그레이션 전환, 메일 도메인·웹훅·대량 본문 표시, 실제 브라우저/iOS 푸시 수신은 운영 활성화 단계의 검증이다. 오래된 FX 정정은 현재/직전 시점 재확인 범위를 넘어서 보장하지 않는다. 이미 전송을 시도한 묶음은 설정 변경 후 다른 신호만 골라 새 키로 자동 재발송하지 않으므로 이력에서 확인한다.

푸시 잠금 화면은 일반 안내만 표시하며 접수는 기기 표시 보장이 아니다. 실제 공급자·전달·배포를 확인하지 않은 상태에서 운영 검증 완료로 해석하지 않는다. 이번 작업은 Git 원격 푸시·배포·실제 발송을 실행하지 않았다.
