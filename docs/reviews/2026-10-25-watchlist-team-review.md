## 채택한 수정과 재현 증거

1. **P2 — 종목 별칭 때문에 가져오기 재시도 중단.** 보유 `BRK.B`와 이미 등록한 `BRK-B`를 동일 종목으로 비교하지 않았다. Chrome 회귀에 이 조합을 추가하자 제외될 항목이 남는 실패가 발생했다. 가져오기 후보·재시도 비교에 같은 정규화를 적용했다. 한국 `.KS`/`.KQ`는 유지하며 실제 등록 검증은 서버가 계속 담당한다.
2. **P2 — 저장 후 응답 유실 시 일괄 규칙 선택 누락.** 서버가 IBM을 저장한 뒤 POST 응답만 실패하도록 주입했다. 새로고침·재시도 후 IBM이 일괄 선택에서 빠지는 실패를 확인했다. 최신 목록에 실제 존재하는 종목의 ID도 선택에 복구하도록 수정했다. 중복 POST 없이 IBM·MSFT가 모두 선택되는 회귀가 통과했다. 모든 409를 성공으로 취급하지 않는다.
3. **P2 — 과거 판정의 시점 불명확.** 정지 규칙에 과거 거래일을 넣고 화면에서 확인할 수 없는 실패를 재현했다. 규칙 상세에 `last_session`을 ‘마지막 정상 평가 거래일’로 표시한다. 이 값은 마지막 성공 평가 커서이므로 모든 실패·미평가 결과의 기준일이라고 표현하지 않는다. 정지 규칙의 과거 결과도 요약에 포함되며 현재 시세 상태와 다르다는 안내를 추가했다.
4. **제거 효과 안내.** 관심종목 제거가 연결 규칙을 중지·보관하고 재추가로 자동 복원하지 않는다는 문구와 명시적 재사용 방법을 화면에 추가했다. 동작과 기존 보관 정책은 변경하지 않았다.

브라우저 모의 API도 서버와 동일하게 미국 점 표기를 정규화하고 저장 후 응답 유실을 표현하도록 보완했다. 기존 실패 모의 응답은 저장 전 실패만 표현해 두 경계를 놓쳤다.

## 남은 항목과 판단

- **P2, 기존 명세 차이:** 기간·방향·가격을 반영하는 쉬운 판정 문장이 없다. 조건 입력의 설명은 일반 문구이고 저장 목록은 원시 params를 표시한다. 최초 명세의 ‘실제 판정 의미 문장’을 충족하려면 10종 각각의 의미와 입력 변경 시 갱신을 검증하는 별도 변경이 필요하다. 이번 관심종목 등록·가져오기 복구 수정에 포함하지 않았으며 완료된 것으로 처리하지 않는다.
- **운영 검증:** 실제 Twelve Data 커버리지·계약·공유 credits 경합, Resend 도메인·수신·웹훅, 운영 DB·Cron·WAF를 확인하지 않았다. 확인과 저장은 각각 공급자 조회를 하므로 Cron과 겹친 등록 트래픽을 포함해 quota 여유를 검증해야 한다. 임의 공급자 대체나 운영 발송 활성화는 하지 않았다.
- **재설계 보류:** 단일 SQL의 계정별 상태 집계와 순차 가져오기에 Redis·새 큐·일괄 API를 추가할 실측 근거가 없다. 실제 지연 또는 정지·보관 규칙 누적 비용이 관측되면 쿼리·보존·페이지네이션을 검토한다. 운영 전에는 공유 종목·대표 장기 지표를 포함한 부하를 추가한다.

다음 단계는 조건 설명 문장의 명세 차이를 해소하고, 운영 활성화 전에 위 실연동 검증을 수행하는 것이다.
