# 포트폴리오 저장 복구와 감사 후속 수정

2026-10-24 · 구현 커밋 `1492dcd` · [수정 전 감사](2026-10-24-existing-feature-audit.md)

## 원인과 수정

최초 저장 충돌의 직접 원인은 비공개 Blob을 압축 조회할 때 반환되는 약한 ETag였다.
이 값을 조건부 저장에 보내면 다른 기기에서 수정하지 않아도 충돌로 거절됐다.
읽기에 `Accept-Encoding: identity`를 지정해 저장소의 강한 ETag를 그대로 사용한다.
MockTransport 검사에서 기존 코드의 실패와 수정 후 연속 저장·진짜 충돌 차단을 확인했다.

| 감사 항목 | 수정과 검증 |
| --- | --- |
| 조회/저장 장애 후 편집 내용 소실 | 요청 전에 전체 상태·기준 버전·시간을 계정 및 초안별 키에 보관한다. 실제 조회 함수로 재접속, POST 실패, 응답 유실, 여러 탭, 계정 전환을 검사한다. |
| 운영 FRED 지표 4개 실패 | 검증 배포의 로그에서 12초 읽기 시간 초과를 확인했다. urllib와 httpx 요청은 실패했고, 기존 yfinance가 사용하는 curl_cffi의 브라우저 호환 요청은 같은 FRED CSV 주소에서 4개 모두 성공했다. 직접 사용하는 의존성을 선언하고 실패 로그를 남긴다. |
| 환율 날짜가 다른 일간 증감 | 외화 종목 또는 외화 현금이 있으면 환율의 현재·이전 날짜도 종목의 비교 기간과 일치해야 한다. 불일치 시 일간 증감만 보류하고 현재 평가액은 유지한다. |
| 위젯 변경으로 최초 자산 자동 업로드 | 서버 자산이 없거나 미해결 초안이 있으면 배치만 브라우저에 보관한다. 명시적 자산·목표 저장 뒤에 계정 배치 자동 저장을 허용한다. |
| 빈 revision으로 조건부 저장 우회 | API 스키마에서 빈 문자열을 422로 거부한다. 실제 HTTP 어댑터까지 연결해 호출 부재, 신규 생성, 조건부 수정, 내부 알림 쓰기 계약을 검사한다. |

재시도는 최신 서버 값을 읽은 뒤 원래 기준 버전이 같을 때만 저장한다. 기준이 다르거나
모르면 자산·목표·배치를 나란히 보여주고 사용자가 선택한다. 선택 이후에도 비교 당시
버전으로 조건부 저장하므로 추가 변경은 다시 충돌한다. 서버 내용을 선택한 경우에도
초안은 별도 복구본에 보관하며, 기존 `before-cloud`·`recovery` 원본을 덮어쓰지 않는다.
여러 초안은 선택 목록에서 확인할 수 있고 복구본은 JSON으로 내보낼 수 있다.

함께 삭제되며, 저장소 차단·용량 부족 시 입력 창을 닫지 말라는 안내를 표시한다.
