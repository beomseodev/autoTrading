# 종가 알림 확장 설계 팀 검토 결과

검토일: 2026년 10월 23일. 코드 기준: `5e6f5eb`.
산출물: [다음 세션 구현 계획](../plans/2026-10-23-stock-alerts.md).

실제 Orca 작업자 네 명이 같은 기준 코드에 대해 독립 검토했다.
참여 역할은 비판·가능성·외부인·확장성이고, 네 역할 모두 완료 보고를 받았다.
누락 또는 공급자 대체는 없다. 공급자는 모두 설정 기본 Codex였고 모델/effort를 임의 변경하지 않았다.
각 작업자는 보고서만 작성했으며 제품 코드 수정·테스트 실행·외부서비스 변경은 하지 않았다.
주 세션은 원문과 공식 외부 문서를 확인하여 아래와 같이 결정했다.

## 채택한 결정

| 쟁점 | 결정과 근거 |
| --- | --- |
| 기존 운영자 메일의 일반 사용자 확대 | Gmail 수신자만 바꾸지 않음. 사용자별 동의·수신주소·규칙·예약 대상 목록·발송 원장이 필요하므로 신규 알림 저장소와 메일 경로를 분리 |
| 저장 방식 | 운영형 기본값은 PostgreSQL. 기존 Blob 전체 이전은 불필요하며 보유자산·목표·배치는 그대로 보존 |
| 일봉 확정 | 최근 행을 무조건 종가로 간주하지 않음. 시장별 달력·시간대·기대 세션·공급 검증·보정 정책을 명세 |
| 다국가 거래일 | 한국·미국 시계열 교집합 정렬을 사용하지 않음. 종목별 세션 날짜와 KST 발송일을 분리 |
| 첫 등록·정지·재개 | 이전에 끝난 신호를 새 돌파로 만들지 않음. 활성화시각·의미버전·소급 범위를 고정 |
| 중복·실패 복구 | 단순 선점 파일로 완료 처리하지 않음. 이벤트·lease·일일 outbox와 공급자 멱등 키를 사용 |
| 시간 초과 | 전체 사용자를 한 요청에서 끝내려 하지 않음. 5분 재개 작업과 호출별 시간 예산을 사용 |
| 화면 의미 | 현재 상태·새 신호·무신호·휴장·자료 부족·조회 실패·메일 접수를 구분 |
| 기존 리밸런싱 | 운영자가 신규 수신에 동의할 때 통합. 전체 해지 후 기존 10시 메일이 자동 부활하지 않도록 전환 상태 보존 |

## 기본값으로 결정한 항목

사용자는 일반 사용자 전체·10종·아침 8시 통합메일을 선택했다.
운영형 기반/베타, 시간 정밀도, 무신호일 수신에 대한 추가 선택은 문서 작성 시 답변이 없으므로
운영형 Neon·Resend·Twelve Data Business, 8시대 발송 목표, 새 신호가 있을 때만 발송을 제안 기본값으로 표시했다.
무료 이용 권한이나 요금을 확인한 것으로 간주하지 않는다. 계정·도메인·데이터 이용 범위·quota는 운영 전 준비 조건이다.

가능성·외부인 검토자의 “무신호일도 매일 요약” 제안은 기본안에서 채택하지 않았다.
알림 피로를 줄이고 이전 조사에서 제안한 사건 중심 알림을 유지하되,
정상 무신호와 장애는 화면에서 구분한다. 사용자가 매일 요약을 선택하면 이 항목을 함께 수정한다.

기존 Blob·Gmail을 이용한 소규모 베타 대안은 공개 다중사용자 최종 구조로 채택하지 않았다.
개인 개발용 코드의 단순성은 장점이지만 수신자 발견·트랜잭션·SMTP 결과 불명 복구 한계가 남는다.
별도 메시지 브로커·마이크로서비스·범용 조건 엔진도 이번 범위에서는 추가하지 않는다.
